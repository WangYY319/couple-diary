界面加载缓慢 / 点击无反应 原因分析与修复

问题现象

进入界面后反应时间较长，点击无任何反应。

根因分析（共5个瓶颈）

#瓶颈影响严重度
1 vocab-data.js 同步阻塞
680KB词库文件在HTML中以 <script> 同步加载，浏览器必须下载、解析完毕后才能执行后续代码		 首屏延迟 2-5秒 严重
2 25+模块同步初始化
App.init() 中依次调用 TabNav.init()、MusicPlayer.init()、EnglishVocab.init() 等25个模块的init方法，全部同步执行		 主线程阻塞 1-3秒 严重
3 双重初始化
模块既在 App.init() 中初始化，又在 enterApp() 中初始化，导致重复执行		 加倍阻塞时间 中等
4 15+云同步同时发起
进入应用后立即同时发起 syncAll、syncPhotos、syncVoices、syncLetters 等15+个网络请求		 网络拥塞、主线程回调堆积 中等
5 visibilitychange 同步风暴
每次切换标签页回来，立即触发15+个同步操作，无任何防抖		 切回应用时卡顿 中等

已实施的修复（v115）

❌ 修复前

HTML同步加载vocab-data.js(680KB)
→ 25个模块同步init()
→ 15个云同步同时发起
→ 用户等待 3-8秒 才能交互

✓ 修复后

移除阻塞脚本，词库用内置fallback
→ 首屏立即渲染(Calendar+Cards)
→ 非关键模块requestIdleCallback延迟
→ 云同步错峰(500ms/1000ms)
→ 用户 <1秒 即可看到界面
  • 移除 vocab-data.js 同步加载：从HTML中删除 <script src="vocab-data.js"> 标签，英语刷词模块使用内置的100词fallback词表。消除680KB文件的阻塞下载和解析。
  • 三阶段初始化架构：将 enterApp() 重构为三阶段——阶段1立即渲染关键UI（日历+卡片+背景），阶段2用 requestIdleCallback 在浏览器空闲时初始化25个非关键模块，阶段3错峰执行云同步。
  • 消除双重初始化：从 App.init() 中移除25个模块的init调用，仅保留在 enterApp() 的延迟初始化中，避免重复执行。
  • 云同步错峰执行：核心同步（syncAll/syncPhotos/syncVoices/syncQuiz）立即执行，次要同步延迟500ms，低优先级同步延迟1000ms，避免同时发起15+请求。
  • visibilitychange 防抖：添加500ms防抖，避免频繁切换标签页时触发同步风暴。次要同步额外延迟500ms。
  • Service Worker 缓存清理：缓存版本升级至v115，移除vocab-data.js的缓存引用，激活时自动清理旧缓存。

网站进入 vs 桌面快捷方式进入：差异对比

两种进入方式的本质区别

维度网站（浏览器地址栏进入）桌面快捷方式（PWA安装）
运行环境 浏览器标签页内运行 独立窗口运行（类原生应用）
Service Worker 由浏览器管理，更新及时
每次打开会检查SW更新		 由系统级PWA容器管理
更新可能滞后，部分系统有缓存
存储隔离 LocalStorage + IndexedDB
绑定到浏览器域名下		 独立的存储分区
可能与浏览器存储隔离
缓存策略 网络优先策略
fetch优先，fallback到cache		 缓存优先策略
部分系统先读缓存，可能使用旧版本

SW更新后立即生效		 需手动更新或等待系统调度

产生差异的核心原因

  • 存储分区不同：桌面PWA安装后，操作系统为其创建独立的存储分区，与浏览器的存储互相隔离。这意味着 LocalStorage 中的配对码、角色信息、历史数据在桌面快捷方式中可能不存在，导致显示未配对状态。
  • Service Worker 更新不同步：浏览器模式下，SW 每次访问都会检查更新；而桌面 PWA 模式下，SW 更新由系统调度，可能延迟数天。导致桌面快捷方式可能使用旧版本代码和旧缓存。
  • 缓存策略差异：当前 SW 使用"网络优先"策略，但在桌面 PWA 中，部分系统（如 Chrome on Windows）会先读取本地缓存，导致显示旧内容。
  • IndexedDB 可能分离：虽然我们在 IndexedDB 中备份了配对码，但桌面 PWA 的 IndexedDB 与浏览器的 IndexedDB 可能是不同的数据库实例，导致备份恢复机制失效。

风险评估

风险严重度说明
配对码丢失 高 桌面快捷方式使用独立存储，LocalStorage和IndexedDB可能不包含配对码，导致显示未配对
数据不一致 高 两端各自的答题记录、照片、语音等本地数据不共享，可能出现"我写了对方看不到"
使用旧版本 中 桌面PWA可能停留在旧SW版本，不获取最新代码，导致功能缺失或bug未修复
同步冲突 中 两端各自推送数据到云端，可能导致覆盖

建议方案

推荐做法：统一使用网站（浏览器）方式进入

你提到"一般都是在网站进入的方式"，这是正确的做法。原因如下：

  • 保留配对码和历史数据：网站方式使用浏览器的 LocalStorage 和 IndexedDB，配对码和历史登录数据完整保留。IndexedDB 备份机制也在此环境下正常工作。
  • 自动获取最新版本：浏览器模式下，Service Worker 每次访问都检查更新，确保始终使用最新代码。本次 v115 性能优化会立即生效。
  • 存储一致性：同一浏览器内，所有数据存储在同一域名下，不会出现存储分区隔离问题。
  • 同步可靠性：云同步通过浏览器网络栈发起，请求头完整，CORS策略正常，MantleDB API 通信更稳定。

关于桌面快捷方式：如果之前安装过桌面PWA，建议卸载桌面快捷方式，统一通过浏览器访问。如需桌面入口，可在浏览器中将网页"添加到书签"或"添加到主屏幕"（移动端），这些方式仍然使用浏览器存储，不会产生存储隔离。
